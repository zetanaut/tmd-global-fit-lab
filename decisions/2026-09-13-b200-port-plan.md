# B200 full-data qualification and throughput plan

The independently reviewed A6000 optimizer pair remains unchanged and runs
concurrently on its own two GPUs. Use a third GPU for a bounded B200 portability
check, rather than changing either paired arm's backend after preregistration.

The allocated B200 engineering gate19811128 passed the same verified container,
190 CPU tests, restart equivalence, exact float64 CUDA arithmetic, CUDA/NVML
identity equality and120seconds of mandatory telemetry. This qualifies the
runtime plumbing only, not the full-data evaluator or optimization performance.

Run `replay-w8-b200-a01` first: all2,290 observations, the exact `anchor-w8`
checkpoint used by the existing CPU/A6000 references, same signed operators,
metric, float64/no-TF32/determinism, numerical tolerances, two directional checks
and zero optimizer updates. Keep the original1,800s model/setup and1,800s saved
audit allowances. Resource review approves1B200/2CPUs/16GiB/65minutes under
`spinquest_standard`; minimum host headroom and memory ceilings are unchanged.
One B200 cell at a time keeps the project at three active GPUs initially.

Only if the width8 full-data replay and endpoint audit pass may exact width16
and24 B200 cells be committed/claimed and run sequentially. A failed numerical
gate stops promotion; it is not repaired by loosening tolerances. Keep every
attempt and any failure evidence. CPU and A6000 reference artifacts remain
immutable, and this hardware experiment cannot select an architecture.

For each outcome report queue delay, setup time from `preparation.json`,
model-window elapsed work, charged forward/VJP counts, sampled GPU/host memory,
and available call-duration evidence. Current counters provide maximum call
duration, not a distribution or average. Historical A6000 same-width timings
are informative but not a controlled hardware benchmark: filesystem load,
concurrent workers and monitoring implementation differ. A speedup claim needs
that qualification or a matched follow-up benchmark. Actual time to result,
including queue and setup, determines whether B200 improves study throughput.

After all three widths pass, B200 becomes an eligible backend for appropriately
preregistered successors. Existing A6000 cells are not migrated mid-run. New
continuations retain scientific identity, saved state and cumulative costs;
hardware identity and residual/numerical differences remain explicit.
